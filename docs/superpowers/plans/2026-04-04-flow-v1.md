# Flow V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Flow as an admin-first multi-tenant billing dashboard with business signup, role-based access, client management, invoices, recurring billing, payments, and a premium dark UI.

**Architecture:** Use a single Next.js app with App Router, server actions and route handlers for protected business workflows, Prisma for PostgreSQL data access, Auth.js for authentication, and Stripe for online payments. Keep all domain data scoped to a `Business` record and isolate concerns into small modules for auth, authorization, billing logic, dashboard queries, and UI surfaces.

**Tech Stack:** Next.js, TypeScript, React, Tailwind CSS, PostgreSQL, Prisma, Auth.js, Zod, Stripe, Vitest, Testing Library, Playwright

## Notes For Implementation

- Prefer server actions and focused domain helpers over oversized route handlers.
- Keep each file narrowly scoped so business logic remains testable without rendering full pages.
- Use seeded demo data only if it helps local dashboard development; do not couple business logic to seed assumptions.
- Centralize permission checks instead of repeating role logic in page components.
- Treat all money values as integer minor units to avoid floating-point bugs.
- Use Stripe webhooks as the source of truth for online payment completion.
- Keep the client portal intentionally thinner than the admin experience in V1.
